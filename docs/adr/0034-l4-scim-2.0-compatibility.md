# ADR-0034：L4 SCIM 2.0 兼容入口

## Status

Accepted。作为 L4 身份能力的补充阶段进入 implementation。

## Context

奇点已经有组织作用域的 SCIM token 和内部批量同步接口，但外部 IdP 不能通过该接口发现、读取、分页和 PATCH 标准 SCIM 资源。仅有批量导入不能证明 SCIM 兼容，也无法覆盖供应商对 Users/Groups 的生命周期调用。

## Decision

1. 增加组织作用域的 `/scim/v2/ServiceProviderConfig`、`/Users` 和 `/Groups` 资源路由。
2. 标准资源和现有批量 `/scim/sync` 共用 `EnterpriseGovernanceService` 的事务 use case；不增加第二状态机、第二 token 表或第二 ACL owner。
3. 使用 `ScimExternalIdentity` 作为外部资源 ID 的唯一映射；`userName` 仅在请求明确省略 `externalId` 时作为 SCIM 资源键。
4. 用户停用复用现有会话/协作/API Key 撤权发布；组成员变化不直接修改文档 ACL。
5. 只实现供应商互操作所需的 SCIM 资源和 PATCH 子集，超出合同的扩展操作稳定返回 400，不在主路径增加 fallback。

## Alternatives

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 继续只暴露内部批量同步 | 实现最少，但不是 SCIM 资源合同 | 拒绝 |
| 引入独立 SCIM 数据库和同步状态机 | 兼容面大，但造成身份与权限事实源分叉 | 拒绝 |
| 在每个 controller 中直接写 Prisma | 能快速出接口，但重复边界和撤权逻辑 | 拒绝 |
| 协议 controller + 既有 service use case | 资源合同清晰，成员状态唯一，测试边界可验证 | 采用 |

## Consequences

正面：常见 SCIM 供应商可使用标准资源路径；读取、PATCH、分页和错误语义可观测；现有 ACL、会话和正文事实源保持不变。

负面：需要维护 SCIM resource schema 和供应商差异测试；完整 RFC 扩展（复杂 filter、Bulk、企业扩展 schema）不在本阶段，未来必须另立兼容范围。

## Security boundary

Bearer token 只在 `ScimTokenGuard` 中解析和摘要验证；controller 不记录 token。所有 resource path 必须显式包含 organizationId，Guard 校验 token 所属组织与路径一致；服务层只接收已验证的组织和最小资源字段。
