# L1身份初始化与注册

## 1. 背景与范围

奇点登录页直接使用思源 `app/src/config/tabs/accountUi.ts` 的账号表单 DOM/CSS（`b3-form__icon`、`b3-text-field`、`b3-button`），只把提交和会话逻辑替换为奇点企业服务。思源官方云账号接口不进入奇点身份链路，因此思源云端区域选择也不进入奇点页面、状态或请求合同。

本期补齐三条用户路径：首次部署创建唯一首个管理员；管理员通过邀请加入成员；用户始终可以创建自己的本地账号。注册入口始终开放，账号注册与组织归属严格分离；新账号不会自动加入任何组织。

密码找回已作为独立身份安全阶段补齐，详见 [`docs/product/l1-password-reset.md`](l1-password-reset.md)；本合同仍不包含邮箱验证和验证码供应商接入。现有 OIDC、SAML、MFA 和邀请接受能力保持合同不变。

## 2. 本地证据与同类参考

| 参考 | 已观察到的交互 | 借鉴与边界 |
| --- | --- | --- |
| 思源原生账号页 `app/src/config/tabs/accountUi.ts` | 用户名、密码、登录、忘记密码、注册链接集中在一个窄表单 | 直接复用 DOM/CSS 和交互密度；登录请求改为奇点本地 API |

## 3. 用户故事

- 作为首次部署管理员，我从部署日志取得固定账号 `admin` 和一次性随机强密码，打开奇点后直接登录。
- 作为已经存在管理员的部署者，我不能再次通过启动或 Web 入口创建第二个 owner、重新生成密码或覆盖现有数据。
- 作为企业管理员，我可以继续生成邀请链接，让被邀请者创建本地账号并按邀请角色加入指定组织。
- 作为普通用户，我始终可以打开注册页创建本地账号，不需要选择云端区域、组织或角色。
- 作为已注册但尚未入组的用户，我能看到自己尚未获得空间访问权限，并等待管理员邀请或分配。
- 作为登录用户，我看到的是思源原生账号页的同一套 DOM/CSS，但登录请求和会话落地使用奇点企业 API，成功后进入奇点空间列表。

## 4. 交互定义

### 4.1 登录

登录页默认展示账号、密码和登录按钮，不展示云端区域选择；已配置企业单点登录时展示企业登录方式，未配置时不展示空的单点登录区域。注册和忘记密码入口始终可用；密码找回遵循 [`docs/product/l1-password-reset.md`](l1-password-reset.md)。安装状态只用于部署说明，不决定注册是否可见或是否允许提交。

登录失败沿用现有不可枚举错误：账号或密码错误、限流、服务不可用分别给出用户可理解的反馈，不透露账号是否存在。成功后只保存内存 CSRF token，路由进入原有 returnTo 或空间列表。

### 4.2 首次管理员初始化

首次部署时 API 自动生成固定用户名 `admin` 和随机强密码，并创建默认组织、首个知识空间、成员关系及 Kernel。密码只在首次部署日志中输出一次；Web 不允许修改用户名或覆盖该密码。登录页只提供本地登录，部署日志是初始凭据唯一来源。

初始化是一次性启动状态转换：空安装只有一个并发启动者可以创建 admin；其他启动者不得重新生成或覆盖密码。已初始化系统重启只读取状态并直接提供登录。

### 4.3 本地注册

注册入口始终显示，注册表单只包含账号、密码和确认密码。成功后只创建本地 User 并签发会话，不创建组织、空间、成员关系或 Kernel 实例；进入空间列表后显示等待组织管理员分配的空态。账号冲突、输入非法或服务不可用时，页面给出对应错误，不把安装状态包装成注册权限。

### 4.4 邀请注册

邀请接受页继续使用现有 token；本地新账号创建后进入被邀请组织，不能选择或提升组织角色。邀请 token、密码和会话 token 不进入 URL、日志或浏览器持久化。

## 5. 业务规则与安全约束

- 奇点本地 `User`、`Organization`、`OrganizationMembership`、`Space`、`SpaceMembership`、`KernelInstance` 和 `AuthSession` 是唯一事实源。
- 首个管理员必须是首个组织的 `owner`，并同时拥有首个空间的 `admin` 权限；普通注册用户没有任何组织角色，直到被邀请或由管理员分配。
- 已初始化后首次初始化入口关闭；注册不能创建已有组织成员，也不能改变已有 owner。
- 登录标识使用现有规范化合同；密码使用现有 Argon2 哈希合同；明文密码只在请求处理期间存在。
- 初始化和公开注册均由后端事务完成；服务端返回 session cookie 与 CSRF token，不把内部 ID 注入页面之外的业务合同。
- 公开接口只做一次 schema 解析；服务层只接收已规范化值；数据库唯一约束负责并发下的最后一致性。

## 6. 验收标准

| ID | 可观察结果 | 风险与测试价值 |
| --- | --- | --- |
| ID-BR-01 | 空数据库首次部署自动生成固定 `admin`、随机强密码、组织、空间和会话 | 当前没有管理员导致系统不可用；真实启动 + PostgreSQL |
| ID-BR-02 | 两个并发 API 启动初始化最多一个成功，失败启动不留下半成品 | 首次部署竞争和重复 owner；事务集成 |
| ID-BR-03 | 已初始化系统不再展示可提交的首个管理员流程，固定 `admin` 直接登录仍可用 | 重复初始化覆盖风险；HTTP + React component |
| ID-BR-04 | 注册入口始终可见且注册请求不依赖安装状态开关 | 用户被错误阻断；HTTP + component |
| ID-BR-05 | 用户注册只创建本地账号并进入空间列表，不产生任何组织、空间或成员关系 | 身份与组织耦合风险；真实 HTTP + PostgreSQL |
| ID-BR-06 | 注册用户看见“尚未获得空间访问权限”，被邀请/分配前不能访问任何组织空间 | 越权入组；授权 HTTP + component |
| ID-BR-07 | 重复账号、非法密码反馈明确，密码不明文落库或进入日志 | 输入和敏感数据风险；合同 + 日志审计 |
| ID-BR-08 | 登录页直接使用思源账号页 DOM/CSS，不展示云端区域选择，亮暗色和 320px 无横向溢出 | UI 复用回归；component + visual |
| ID-BR-09 | 初始化、注册和登录成功后都清理旧 Query/CSRF 状态，迟到请求不能覆盖新会话 | 会话代次污染；component + browser integration |

## 7. 非目标

本期不提供邮箱确认、验证码图片、邀请邮件投递、跨组织账号合并或外部身份供应商自动建组织。管理员没有可投递邮箱时仍按部署凭据恢复流程处理；普通用户密码找回遵循 [`docs/product/l1-password-reset.md`](l1-password-reset.md)，不能通过注册接口隐式扩展。
