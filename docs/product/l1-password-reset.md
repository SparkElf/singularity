# L1密码找回

## 1. 背景与范围

登录页必须为忘记密码的用户提供可完成的恢复路径，而不是只有登录和注册。找回流程使用注册时的邮箱账号接收一次性链接；链接失效、已使用或密码不符合现有密码规则时，页面给出可采取的下一步。重置成功后，该账号的全部旧会话立即失效，用户回到登录页使用新密码登录。

本期不改变思源原生登录表单的视觉表面，不新增组织、空间或内容权限逻辑，不把重置令牌放入 API 响应、日志、数据库明文或浏览器持久化。首次部署固定账号 `admin` 没有邮箱时不能通过公开找回页恢复，页面明确引导联系部署管理员。

## 2. 本地参考与决策依据

| 参考 | 已观察到的交互 | 借鉴与边界 |
| --- | --- | --- |
| 思源原生账号页 `app/src/config/tabs/accountUi.ts` | 登录表单在主按钮后放置账号辅助入口，使用同一套 `b3-*` 类名和主题 token | 忘记密码入口继续放在登录按钮下方，跳转到奇点恢复页；不接入思源云账号接口 |
| 奇点现有本地登录与会话链路 | 登录标识已规范化，密码由 Argon2 处理，会话可按用户批量撤销 | 重置只复用这些公开合同，不在控制器重复校验或另建会话体系 |
| OWASP 常见恢复合同 | 未知账号与已知账号返回相同成功语义，令牌单次、短期、只存摘要 | 用于避免账号枚举和重放；邮件发送失败只记录完整异常，不把敏感 token 写日志 |

本仓库已有的登录、会话、密码哈希和审计实现足以承担主体链路；外部 SMTP 仅作为传输依赖，不引入新的身份事实源。

## 3. 用户故事

- 作为忘记密码的用户，我能从登录页找到“忘记密码”，输入注册邮箱并收到恢复链接。
- 作为收到链接的用户，我能在有效期内设置新密码，成功后旧浏览器和其他设备都不能继续使用旧会话。
- 作为输入错误或不存在邮箱的用户，我看到不会泄露账号是否存在的统一结果，并能返回登录页。
- 作为部署管理员，我能在没有 SMTP 配置时看到明确的服务未配置提示，而不是收到一个永远不会到达的假成功。

## 4. 交互定义

### 4.1 登录页

登录按钮下方保留思源原生密度的辅助入口“忘记密码”，链接到 `/forgot-password`。入口不携带账号、组织或空间参数；返回登录时保留当前页面的主题和布局。

### 4.2 请求找回

恢复页只显示邮箱输入、提交按钮和返回登录。提交成功后显示统一文案“如果该邮箱已注册，你会收到一封密码重置邮件；请检查收件箱和垃圾邮件。”，无论账号存在与否都不显示用户 ID、组织名或发送地址。若实例未配置 SMTP，所有请求统一显示“密码找回服务尚未配置，请联系管理员”，不执行账号查询，避免配置状态与账号存在性组合成枚举信号。

### 4.3 设置新密码

邮件链接打开 `/reset-password?token=...`。页面只从 URL 读取一次性 token，提交新密码和确认密码到重置接口。成功后清理本地会话状态并跳转登录；token 过期、已使用或不存在时显示“链接已失效，请重新申请”。页面不得把 token 回填到可见文本、剪贴板、日志或持久化存储。

## 5. 业务规则与安全约束

- 请求找回的唯一用户输入边界是邮箱 schema；控制器完成一次解析，服务层只接收规范化邮箱。
- 找回请求复用现有按来源和账号标识的限流 owner；达到上限时返回既有 429/Retry-After 合同。
- 重置提交同样复用限流 owner，先限制高成本密码哈希尝试，再进入令牌事务。
- 重置令牌由密码学安全随机数生成，数据库只保存带域隔离的 SHA-256 摘要；有效期 30 分钟、单次消费。
- 消费令牌、更新密码、标记令牌已使用、撤销该用户全部会话必须在一个数据库事务内完成；并发消费最多一次成功。
- SMTP 发送器由 Nest DI 注入，生产使用配置的 SMTP URL 和发件人；测试使用捕获发送器。邮件正文包含实例公开地址和令牌链接，不包含密码、会话 token 或组织权限。
- 发送器异常记录原始异常对象和完整堆栈，并以统一成功语义结束已进入投递阶段的请求；未配置发送器时在查询用户前统一返回服务未配置。
- 既有 `PasswordHasher` 是密码哈希唯一 owner；既有 `revokeUserSessionsInTransaction` 是旧会话撤销唯一 owner，不在新服务复制实现。

## 6. 验收标准

| ID | 可观察结果 | 风险与测试价值 |
| --- | --- | --- |
| PWR-01 | 登录页显示思源原生风格的“忘记密码”入口，并可进入恢复页 | 用户无法发现恢复路径；组件 + 浏览器集成 |
| PWR-02 | 有效邮箱请求后返回统一结果并收到含一次性链接的邮件 | 主业务链路不可用；真实 HTTP + 捕获外部邮件边界 |
| PWR-03 | 不存在邮箱与已存在邮箱的响应状态和用户可见文案一致 | 账号枚举；HTTP 合同 |
| PWR-04 | 未配置 SMTP 时请求在查询账号前统一返回服务未配置提示 | 部署误配与枚举组合风险；HTTP 合同 |
| PWR-05 | 有效链接可设置新密码，成功后旧会话全部失效且新密码可登录 | 会话撤销和密码更新原子性；PostgreSQL 集成 |
| PWR-06 | 过期、已使用、伪造 token 均不能改密，页面给出统一失效提示 | 重放和篡改；HTTP 合同 + 集成 |
| PWR-07 | 新密码沿用现有 12–128 Unicode 字符规则，确认密码不一致时不发请求 | 边界和用户反馈；组件 |
| PWR-08 | 亮色、暗色、320px 视口无横向溢出、重叠或不可读错误；浏览器无 console/pageerror/requestfailed | 原生主题回归；浏览器集成 + 视觉 |

## 7. 非目标

本期不做邮箱验证、验证码供应商、短信找回、管理员代替用户改密页面、跨组织账号合并或云端账号同步。管理员没有可投递邮箱时仍按部署凭据恢复流程处理。
